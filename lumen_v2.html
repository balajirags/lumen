04 / modes
Output modes

One graph, four ways to consume it

The same KuzuDB graph powers all four modes — full docs pipeline, two MCP server variants, and an interactive graph explorer.

lumen run
Full docs pipeline
Preflight → indexer → 3 analysts + architect → MkDocs Material site with Mermaid + C4 PlantUML. Multi-repo accumulation.
→ output/<repo>-<ts>/ · http://localhost:8081
lumen mcp
stdio MCP server
Indexes repo then exposes 36 graph tools over Model Context Protocol stdio. Ideal for local process-based clients like Claude Desktop.
Claude Desktop · Cursor · Zed
lumen mcp-http
Streamable HTTP MCP
Serves an existing DB or indexes fresh — then exposes a URL-based MCP server. Simplest client UX for VS Code, Docker, and cross-workspace use.
→ http://127.0.0.1:8765/mcp
make compose-ui
Graph visualization UI
React 19 + Sigma.js explorer with three-panel layout: query panel, graph canvas, node detail. Supports KuzuDB and Neo4j backends.
→ http://localhost:3002
xlarge repos: docker-pipeline stops at preflight → use docker-mcp instead

06 / economics
Token economics

Graph-first scales. Raw-file reading doesn't.

CPG query tokens (lumen)
5–10k
tokens for full architecture analysis across all three analysts via graph queries
Naive full-repo file reading
500k–2M+
tokens — often impossible before hitting context limits on medium repos
Example run total (recent)
339k
311k input + 28k output · cost = provider price × token split · check pipeline.json
MCP reuse advantage
$0.00
re-query indexed graph over MCP without re-running the full pipeline · Ollama also free

Cost depends on provider, model, and the input/output split — output tokens are materially more expensive on Sonnet-class pricing. Use pipeline.json for grounded estimates. Analysts use get_method_source only for business-critical logic (50–600 tokens per call).

Token usage logged to pipeline.json · MCP reuse indexes once, queries many times for free

07 / quickstart
Quickstart

Four commands. Full docs + MCP + UI.

bash — Docker (no Java/Node/Python needed)
# build the pipeline image once
$ git clone <repo> lumen && cd lumen && make docker-build
# run full docs pipeline (3 analysts + architect → MkDocs site)
$ make docker-pipeline REPO=/path/to/repo ARGS='--provider anthropic --model claude-sonnet-4-6'
› [preflight] repo metrics · risk: medium · 42k LOC
› [indexer] Java ✓ · JS/TS ✓ · Python ✓
› [analysts ∥] domain · flows · tech — running in parallel ...
› [architect] reading Phase 2 artifacts → writing target state ...
› [builder] MkDocs site written → output/myrepo-20260406/
# xlarge repo? skip docs pipeline and use MCP mode instead
$ make docker-mcp REPO=/path/to/repo
› MCP HTTP server → http://127.0.0.1:8765/mcp
$ make docker-docs   # serve docs → http://localhost:8081
$ make compose-ui    # graph explorer → http://localhost:3002
Docker (recommended — zero prerequisites) · Native: make install && make run · Ollama: --provider ollama --model qwen2.5:32b
Also: OpenAI · self-hosted Ollama · --repo-size-check off|warn|strict
